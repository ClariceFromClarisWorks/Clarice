# Batch3E focused acceptance

`host.py`: actual namespace/removal code; 1969 negative control, literal catalog
names, protected siblings (data/resource bytes and metadata), native I/O failure,
allocation failure, cancellation, retry and cleanup under ASan/UBSan.
`glob.py`: actual native wildcard code, shared encoding and511/512-byte bounds.
`guest.py`: normal68000 Snow on disposable cloned Batch3D disks; needs the existing
`fsprobe` and resource-rich `/tmp/batch3b/source`. Optional numeric argument resumes
a failed test after a fixture-only correction. It never contacts physical Macs.
`performance.py before|after`: identical100-file copy/removal and1000-file find/du
fixtures on Perf; three runs, guest total/load/execution ticks and native heap.

Boundary: whole native dot names become `%2E`/`%2E%2E`. Raw Unix `.`/`..` remain
navigation. `%` is quoted before re-entry, so escape-looking names decode only
once; `/` stays `%2F`. Colon/NUL are rejected by existing native component decoding
and cannot be valid HFS catalog children. Ordinary parent components stay unchanged.
Recursive rm/cp and mv fallback, find/du output, listing/completion, native-path
conversion and native wildcard expansion now share the same name convention.
No filesystem identities, traversal frames or resolver semantics are redesigned.
