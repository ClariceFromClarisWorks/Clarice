# Clarice native command ABI — implementation specification

Target: 68000, 32-bit C integers/pointers, the same pinned Retro68 C calling convention as Clarice. A compiler probe confirms ordinary code/global/string references use R_68K_32 relocations. Commands are cooperative in-process programs, not protected Unix processes.

A build-time packer converts an ELF relocatable object to a bounded CLX1 image. The header carries ABI version, image length, entry offset, relocation/import counts and a checksum. Code, read-only data, data and zeroed BSS share one loaded allocation. Imported symbols resolve only through an explicit runtime export table. The loader validates every length, offset, symbol name and relocation before calling `int clarice_main(int argc, char **argv)`. Unsupported CPU/ABI/relocation formats fail with status 126. Missing PATH commands return 127. A fresh image is loaded per invocation so static data is reset. One command is active at a time and its image is released on return.

Standard streams and filesystem services are runtime interfaces, not embedded command dispatchers. The core-utility module contains the actual ls/df/cat implementations; namespace utilities such as mkdir, rm and ln currently remain builtins. It may be a multicall module exposed by separate /bin names, like established Unix multicall packages. It must not delegate utility execution back to shell builtins.

No fork emulation, process isolation or arbitrary binary ABI compatibility is promised. Concurrent pipe execution requires a further scheduling/runtime design; the existing bounded spool pipeline is explicitly sequential. Streaming EOF, standard error, redirection ordering, status propagation and cleanup are validation gates. Upstream ports must keep source/licence/provenance and adaptations separable.

Implemented scope: `cli_read(0, buffer, count)` and `cli_write(1|2, buffer, count)` return byte counts or -1; zero read is EOF. The core module also imports private native File Manager/runtime services through the explicit table in src/module.inc. These private imports do not constitute a general libc ABI. Modules built for a different CPU/API/library ABI are not portable to this loader. The current Plus image is 11,200 bytes including relocations/import names; it is released after each call. The installer copies the same multicall image to ls, df, cat, benchls and benchscan. There is no resident utility-code cache.
